# Eye-in-Hand 手眼标定操作指南

## 1. 概述

Eye-in-Hand 标定用于求解 **手部相机(D435) 到 机械臂法兰(flange)** 的刚体变换 `T_cam2flan`。

标定完成后，可通过以下坐标链将相机观测转换到机器人基座坐标系：

```
P_base = T_flange2base × T_cam2flan × P_camera
```

### 核心原理

相机固定在机械臂末端，棋盘格固定在外部。机械臂移动到 N 个不同位姿，每个位姿同时记录：
- 机械臂法兰位姿（正运动学已知）
- 相机观测到的棋盘格位姿（PnP 求解）

由此构建方程 `A·X = X·B`，其中 X 即为待求的 `T_cam2flan`。

### 3.2 标定板放置要求

根据实际标定图像，标定板的正确放置方式如下：

**当前实际做法：标定板平放在地面上**
- 标定板（DFVision B12-4）贴在白色刚性底板上
- 白色底板平放在地板/桌面上
- 机械臂从上方俯视拍摄

**关键要求：**

| 要求 | 说明 |
|------|------|
| **绝对静止** | 整个采集过程中标定板不能有任何移动，用夹具/胶带牢牢固定 |
| **平整无翘曲** | 标定板必须贴合在刚性平面上，不能弯曲、翘起 |
| **光照均匀** | 避免强反光（尤其是塑封膜反光）、避免阴影遮挡角点区域 |
| **无遮挡** | 标定板周围清理干净，不要有杂物遮挡边缘 |
| **合适距离** | 标定板放在机械臂工作空间内，相机距标定板约 30~50cm |

### 3.3 相机安装确认

- D435 相机通过支架固定在 Piper V2 的法兰（link6 末端）附近
- 相机与法兰之间的相对位置在整个标定过程中**不能变化**
- 确认 USB 线连接稳固，不会在机械臂运动时脱落

## 4. 标定操作流程

### 4.1 启动数据采集

```bash
cd /data/workspace/MobileManipulator2/src/handeye_calibration
export PATH="/usr/bin:$PATH" && python3 handeye_data_collect_piper_v2.py
```

选择：
- 标定模式 → `1` (Eye-in-Hand)
- 采集模式 → `1` (Manual，首次标定) 或 `2` (Replay，复标)

程序自动完成初始化：连接机械臂 → 移到初始位 → 关闭夹爪 → 启动 D435 (1280×720, 15fps) → 弹出预览窗口。

### 4.2 手动采集：逐帧操作步骤

目标：采集 **≥60 帧**，每帧位姿不同，确保质量过滤后仍有 **≥30 帧** 参与标定计算。以下是**每一帧**的完整操作，从头到尾按顺序做：

---

#### 第 1 步：进入示教模式，拖动机械臂到新位姿

Piper V2 支持拖动示教——通过机械臂上的**物理按键**进入示教模式，关节松弛后用手拖动。

**操作：按下机械臂底座上的「拖动示教」按键，指示灯变化后即进入示教模式。**

进入示教后，**用手握住机械臂连杆末端**（靠近法兰处），缓慢平稳地拖到目标位姿。

**拖动时的实操要求：**

- **握哪里**：握连杆，不要直接握相机或 USB 线，否则可能改变相机与法兰的相对位置，标定作废
- **怎么拖**：缓慢、匀速，不要猛拉猛推。松手时轻轻放，不要突然撒手让臂弹跳
- **拖多远**：每帧相对上一帧，位置至少变化 5cm，姿态（倾斜方向）也要有明显变化。具体多样性要求见第 5 步
- **拖到哪**：确保相机镜头仍然大致朝向标定板方向。如果拖过头，棋盘格会出画

松手后观察：如果机械臂在重力下明显下坠，说明这个姿态关节力矩不够支撑，换一个不那么极端的姿态。

---

#### 第 2 步：退出示教模式，锁定关节

**操作：再次按下机械臂底座上的「拖动示教」按键，指示灯恢复后即退出示教模式。**

退出后关节锁死，机械臂保持当前姿态不动。

**注意：绝对不能在示教模式（关节松弛）下拍照。** 示教模式下臂会晃动、下坠，位姿不稳定，拍出的数据无法使用。

---

#### 第 3 步：等待机械臂完全稳定

退出示教的瞬间，关节锁定会产生一个微小的振荡。必须等这个振荡完全衰减后再拍照。

**怎么判断稳了：盯着预览画面中棋盘格上绘制的彩色角点线条，默数 3 秒，线条完全不动才算稳。**

| 情况 | 最少等待时间 |
|------|-------------|
| 退出示教后（正常姿态） | 3 秒 |
| 退出示教后（臂伸展较远、大幅度调整后） | 5 秒 |
| 有外部振动（旁人走动、碰了桌子） | 等振动停止后再数 3 秒 |

如果等待期间观察到以下现象，说明还没稳：
- 预览画面中角点彩色线条在微微晃动
- `DETECTED` / `NOT DETECTED` 状态在闪烁交替
- 终端有机械臂位姿读数在跳变

---

#### 第 4 步：确认棋盘格完全可见

在预览画面中逐项确认：

```
□ 画面顶部显示绿色 "Chessboard: DETECTED"
□ 棋盘格 11×8 所有角点都在画面内，四条边没有被裁切
□ 棋盘格距画面边框有余量（不要贴着边缘）
□ 没有反光白斑盖住角点（塑封膜标定板容易反光）
□ 没有阴影横跨角点区域（机械臂自身投影）
```

**如果显示红色 "NOT DETECTED"：**

不要强行拍照。重新进入示教模式（回到第 1 步），微调位姿，按以下优先级排查：

1. 棋盘格被画面裁切了 → 移动让整块板居中
2. 有反光遮挡角点 → 稍微调整倾斜角避开反光
3. 距离太远、板太小 → 靠近到 30~50cm
4. 倾斜太大、透视畸变严重 → 减小倾斜到 ±30° 以内
5. 画面模糊 → 臂还没稳，回到第 3 步继续等

---

#### 第 5 步：规划本帧的位姿多样性

拍照前先想一下：这一帧和之前已拍的帧相比，是否提供了新的信息？

**核心原则：每帧都必须同时改变位置和姿态，不能只动一个。**

原因：标定方程 `AX=XB` 需要位置和旋转都有独立变化才能求解。只平移不旋转 → 旋转求不准；只旋转不平移 → 平移求不准；所有位姿在同一平面 → 方程退化。

**按以下节奏覆盖 60+ 帧：**

```
帧  1~10：中心区域
  在标定板正上方，小幅改变倾斜方向（±5~10°）
  分别绕 Roll / Pitch / Yaw 各倾斜几次

帧 11~20：向左、向右偏移
  相机水平平移 5~10cm，同时倾斜方向跟着变

帧 21~30：靠近、远离标定板
  改变相机到标定板的距离（25cm~50cm），同时加大倾斜（±15~20°）

帧 31~40：向上、向下偏移
  相机垂直方向移动 5~10cm，改变 Pitch/Roll

帧 41~50：对角线方向、组合运动
  同时大幅改变位置+姿态，覆盖之前没去过的方向
  倾斜角加到 ±20~25°

帧 51~60+：查漏补缺
  回顾终端输出的位姿分布，找到覆盖薄弱的区域
  专门补拍：未充分覆盖的旋转方向、距离段、偏移方向
```

**如果拍了几帧发现自己只是在同一个方向上来回微调——停下来，有意识地往没覆盖的方向大幅移动。**

---

#### 第 6 步：按空格拍照，确认成功

确认上述条件全部满足后：

1. 按 **空格键**
2. 终端打印 `✅ 已采集第 N 帧`，以及当前位姿 `X=...mm Y=...mm Z=...mm` 和 `棋盘格: 检测成功`
3. 扫一眼位姿数据，对比上一帧是否有明显变化

如果终端显示 `棋盘格: 未检测到`，这帧数据质量有问题，后续计算时会被过滤掉。建议调整后重拍。

---

#### 第 7 步：回到第 1 步，采集下一帧

重新进入示教模式，拖到下一个位姿，重复整个流程。

每帧完整流程汇总：

```
进入示教 → 拖到新位姿 → 退出示教锁定
  → 等 3~5 秒稳定 → 确认棋盘格完整可见
  → 确认位姿多样性足够 → 按空格拍照
  → 确认终端成功 → 进入示教，下一帧
```

---

#### 采集完毕：按 ESC 结束，自检多样性

拍完 60+ 帧后按 **ESC** 结束。回顾终端输出的所有位姿数据，检查：

```
帧数要求：
  □ 总采集帧数 ≥ 60
  □ 棋盘格检测成功帧数 ≥ 50（预留过滤余量）

位置范围（X/Y/Z 都应有明显变化）：
  □ X 范围 ≥ 80mm（例如 250~350mm）
  □ Y 范围 ≥ 80mm（例如 -50~+50mm）
  □ Z 范围 ≥ 80mm（例如 250~350mm）

姿态范围（Roll/Pitch/Yaw 都应有变化）：
  □ Roll 变化 ≥ 15°
  □ Pitch 变化 ≥ 15°
  □ Yaw 变化 ≥ 15°
```

如果某个维度变化不足或帧数不够，**不要结束**，继续补拍直到满足全部要求。

### 4.3 Replay 轨迹回放（复标用）

首次手动采集成功后，以后复标可以直接回放那次的轨迹，无需人工操作：

```
采集模式: → 选 2 (Replay trajectory)
→ 选择历史数据集序号
```

回放时程序自动执行与手动采集相同的"移动 → 稳定 → 拍照"流程，区别在于：
- 用**关节角度**精确复位（不是笛卡尔位姿），100% 可复现
- 每帧之间先回零位，消除路径依赖
- 到位后自动等待 **5 秒稳定 + 2 秒沉淀**（共 7 秒）
- 自动拍照 + 自动检测角点

不需要人工干预示教、稳定判断或多样性规划——这些在首次手动采集时已经定义好了。

### 4.4 致命错误清单

| 错误 | 后果 | 解决 |
|------|------|------|
| 示教模式下按了空格拍照 | 臂松弛晃动，数据无效 | 必须先退出示教再拍 |
| 拍照时臂还在晃 | 位姿与图像不匹配，RANSAC 淘汰 | 等 3~5 秒，角点线条不动再拍 |
| 握着相机拖动 | 相机-法兰相对位置变了 | 只握连杆，不碰相机 |
| 棋盘格被裁切/只拍到一部分 | PnP 求解失败 | 确保全部 11×8 角点在画面内 |
| 采集中途标定板被碰动了 | 全部数据不一致 | 丢弃全部，重新开始 |
| 所有帧位姿差不多（共面） | 标定方程退化 | 三个方向都要有运动+旋转 |
| 只改位置不改姿态 | 旋转求不准 | 每帧都必须有倾斜角变化 |
| 总帧数不够（<60帧） | 过滤后有效帧不足 | 至少采集 60 帧，确保过滤后 ≥30 帧参与标定 |

## 5. 标定计算（离线）

**无需硬件，可在任何电脑上运行。**

### 5.1 运行

```bash
cd /data/workspace/MobileManipulator2/src/handeye_calibration
export PATH="/usr/bin:$PATH" && python3 handeye_calibrate.py
```

### 5.2 交互选项

```
1. 系统自动列出所有数据集（按时间倒序）
2. 输入序号选择数据集（或输入 'all' 批量计算）
3. 选择标定模式 → 1 (Eye-in-Hand)
4. 选择角点检测方式:
   - 1: 使用已保存的角点（快速，通常选这个）
   - 2: 从图像重新检测角点（更精确但慢）
```

### 5.3 计算流水线（9 步自动执行）

```
Step 0: 加载配置（棋盘格 11×8, 30mm）
Step 1: 加载数据 + 相机内参，校验模式和相机ID一致性
Step 2: 数据质量过滤（位移/旋转/边界/倾斜角）
Step 3: 数据准备 — PnP 求解棋盘格位姿，构建变换矩阵
Step 4: 重投影误差过滤 — 移除 >2.0px 的帧
Step 5: RANSAC 几何一致性过滤 — 阈值 6mm，移除 outliers
Step 6: 多算法融合 — Tsai/Park/Horaud/Daniilidis/Andreff 并行，选最优
Step 7: L-BFGS-B 非线性优化 — 精细化最优结果
Step 8: 评估 — 计算平移/旋转重复性误差
Step 9: 保存结果 — JSON + YAML 格式
```

### 5.4 质量评级标准

| 等级 | 平移误差 | 旋转误差 | 说明 |
|------|----------|----------|------|
| 🌟 优秀 | < 2mm | < 0.3° | 高精度抓取可用 |
| 👍 良好 | < 5mm | < 0.5° | 常规抓取可用 |
| ⚠️ 可接受 | < 10mm | < 1.0° | 粗定位可用，建议重标 |
| ❌ 需改进 | ≥ 10mm | ≥ 1.0° | 不可用，必须重新采集 |

## 7. 重要概念说明

### 7.1 命名约定

代码中沿用 OpenCV 惯例，变量名使用 `gripper`，但实际指的是**法兰(flange)**：

```
代码中的 T_cam2gripper  ≡  实际的 T_cam2flange
代码中的 T_gripper2base ≡  实际的 T_flange2base
```

输出文件使用 `camera_to_flan` 反映真实语义。

原因：`arm.get_position(return_gripper_center=False)` 返回的是法兰坐标系位姿。

### 7.2 相机内参

标定过程使用的相机内参保存在：
```
src/handeye_calibration/config/hand_camera_intrinsics_piper.yaml
```

包含 D435 多个分辨率的内参（640×480 / 1280×720 / 1920×1080 等），采集时使用 **1280×720**。

### 7.3 坐标系变换链

```
Target(棋盘格) → Camera(相机) → Flange(法兰) → Base(基座)
                  ↑                ↑
             T_target2cam     T_cam2flange (待标定)
```

标定方程：
```
T_flange2base_i · T_cam2flange · T_target2cam_i = T_target2base (常量)
```

## 9. 故障排查

| 现象 | 可能原因 | 解决方法 |
|------|----------|----------|
| 棋盘格始终检测不到 | 距离太远 / 反光 / 不完整 | 调整距离至 30~50cm；调整光照避免反光；确保所有角点在画面内 |
| RANSAC 过滤掉太多帧 | 位姿多样性不足 / 标定板被碰动 | 增加位姿差异，确保三轴运动；重新固定标定板 |
| 标定误差 >10mm | 数据共面 / 有效帧不够 | 确保位姿不共面；总采集 ≥60 帧，有效帧 ≥30 |
| 回放时位置偏差大 | 旧格式数据无关节角 | 使用新格式数据（含 joint angles），关节控制精确 |
| 相机连接失败 | USB 松动 / 设备号冲突 | 检查 USB 连接；确认 SN 337122071190 |
| "模式不一致" 报错 | 采集时和计算时选了不同模式 | 确保两步都选 Eye-in-Hand |
| "相机不匹配" 报错 | 配置文件的 serial_id 与数据不符 | 检查 `calibration_config_piper.yaml` 中的 serial_id |
