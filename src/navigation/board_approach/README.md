# 连续粗接近、末段观测直接切换、垂直精对准

默认 DeepSeek 相机识别＋LiDAR 距离和法向、无 ArUco。目标是沿物体正面法向停靠，车头垂直朝向正面中心。只用本次实时观测，不存取固定目标地图坐标。

## 使用

Mac（会驱动机器人，需在现场看护并可急停）：

```bash
ssh -t didi@192.168.112.106 'bash /home/didi/junbin.zhang/MobileManipulator2/scripts/go_to_board.sh --no-aruco --detector deepseek --geometry-source lidar --standoff 0.934 --target "洗衣机"'
```

加 `--check` 做静态观测、粗阶段规划和异步反馈预检，不启动底盘。`go_to_object.sh` 为同一入口。`--aruco` 使用当前 7×5 标定板编号检测，不调用模型，默认使用原双目深度；与 `--no-aruco` 互斥。
`--geometry-source lidar|depth` 显式选择几何来源。默认无 ArUco 使用 LiDAR；保留 `--geometry-source depth` 回到旧双目方式。两种来源不在失败后自动互相回退。目标检测单独输出二维区域，LiDAR 模式不会先验证相机深度，因此相机空洞不会阻断雷达测量。
`--standoff` 为底盘参考点到目标正面的水平法向距离，支持 0.5～2 米，不是保险杠间隙。默认 0.934 米：按车头前伸 0.434 米计算，对正时车头间隙约 0.5 米；到达距离容差仍为 ±0.10 米。Ctrl+C 中止并清理本程序持有的底盘。

## 两阶段流程

1. 起步前三帧静态观测：目标中心需一致；远处法向允许有界误差，仍必须得到粗法向以保留侧向调整空间。
2. 粗接近：Nav2 连续导航到法向外侧 `max(2.0, standoff+0.8)` 米的预对准点。不再每半米停止，也不把路线切成反复点转向的短直线段。
3. 行走期间后台检测：最多一个请求在途，不积压旧帧，最快约每 2 秒启动一次。ROS 取图在主线程，模型请求和深度计算在工作线程，底盘控制在独立进程。
4. 粗接近末段已有一帧新鲜有效测量时直接切入精接近，不停车补帧；无有效帧时才停车获取一帧。两段共用底盘驱动和异步检测线程。
5. 到位后静态验收。失败则报告并保持停止，不自动多轮试走。

粗接近到精对准之间不强制安排观测停车，必要时最多一次停车复核，不包括起点和最终停止；实际控制器转向、避障、急停或传感器异常仍可要求停车，不能保证任何场景都保持非零速度。

## 异步测量与修正

运动采图匹配 100ms 内的定位位姿，检测结果使用**拍摄时位姿**变换到地图。双目模式要求 RGB/对齐深度同时间戳。LiDAR 模式要求扫描头时间戳与图像相差不超过 60ms，并用 `/fastlio/odom_measurement` 的扫描结束测量时间戳逐点插值补偿到图像时刻；实际应用 body→base_link 外参，不使用改写时间戳和 frame 名字的 `/odom` 转发消息做补偿。不依赖双目深度的有效性。仅支持 robot02 当前 RS16 发布器的 `point_time = header + time - 0.1s` 约定，点时间、里程计覆盖或坐标系不符则拒绝。

粗接近途中没有有效检测时继续执行已确认目标，不用过期结果修正路线；到粗终点不因目标反馈过期而报错。距离粗终点 0.4 米内冻结目标修正，末段检测仍继续，优先复用最新有效观测切换；仅无有效帧时停车取得一次有效静态观测，未通过则不进入精对准。精对准也沿用已验证目标：过期或暂缺反馈不触发中途停车，有新鲜有效测量时以受限、平滑方式更新目标，终点附近也允许更新。精对准目标变化至少 3cm 或 2 度才提交，最多每 3 秒一次，并始终锚定本阶段初始目标，防止累积漂移。到达后必须重新取得三次有效静态测量并通过最终到位检查，Nav2 完成不等于任务成功。目标相对阶段初始中心偏移超过 25cm 也停止：LiDAR 平面对准检查水平中心，允许高柱子的可见区域高度随视角变化；旧双目模式检查三维中心。格式错误或未检测到物体的单帧保留日志，不刷新有效反馈时间。`--check` 需收到至少三次有效异步更新（25秒预算），实际启动运动前至少一次新鲜有效更新。

粗阶段对新的法向和中心做 20% 权重的小幅修正，法向偏离初始值大于 25°不用于更新；新停靠点必须保持在初始停靠点 35cm 内。目标变化至少 12cm 或 5°且更新间隔至少 3 秒时，向 Nav2 提交新目标，由行为树重新规划，无需重启驱动。精对准阶段同样采用受限平滑更新，更新门槛见上文。

## 深度和法向阈值

LiDAR 模式：静态和异步共用表面几何与 6 米距离上限；候选点前向深度筛选保留到 7 米以容纳倾斜面，最终中心仍须不超过 6 米。识别距离与单段 4.5 米路径预算分别检查，不能据此自动行走 6 米。目标区域宽、高各内缩至 50%，剔除地面；至少 25 个平面内点、70% 内点比例、2 条扫描线、二维空间覆盖和图像覆盖验证。RANSAC 及后续平面检查的内点容差 2.5cm，实际使用法向的平面 RMSE 不超过 1.5cm。左右半区各自独立拟合，至少 10 内点及两条扫描线，使用左右单位法向的归一化平均。以下双目深度阈值只用于 `--geometry-source depth`，跨帧方向验证和到位阈值两种模式共用。

投影复用项目 `camera_driver/config/extrinsics_lidar_to_top_camera_optical_frame.yaml`，沿用已知 rs16_lidar→rslidar 和 RGB optical frame 对应关系，同时使用实际 RGB 内参和畸变。程序内部显式计算变换，不修改或补发全局 TF。相机或雷达安装位置改变必须重新标定，不能仅修改坐标系名字。

- 深度平面内点容差：1.5 米内 2cm，按深度平方递增，4 米封顶 5cm；RMSE 上限为对应容差的 60%。至少 80% 平面内点。
- 左右半区相对整体法向：1.5 米内 8°，4 米封顶 20°；通过后使用左右单位法向的归一化平均。
- 远处三帧方向跨度可随深度放宽，4 米封顶 20°；必须离最终区域足够远。过渡停车和最终验收采用严格 0.12rad 跨帧跨度，不继承远处容差。
- 到位：法向距离误差、横向误差均不超过 10cm，朝向误差不超过 5°。

这些是经验阈值，不是精度保证。曲面、遮挡、框错落在背景或深度差可能造成拒绝或误估，需要实机验证。当前粗起步仍要求可靠粗平面；过近且不在适合站位时要求人工重新摆位。

## 安全与预算

速度限制 0.10m/s，禁止倒车、横移。独立底盘进程检查定位、扫描、CAN 状态、速度流、前进和转向避障，驱动的 0.4 秒命令看门狗必须启用。前方 0.9 米、左右各 0.48 米停车包络及转向 0.65 米净空检查保持生效。

底盘初始化后、提交 Nav2 目标前，以零输出最多等待 8 秒，要求收到年龄不超过 6 秒的有效视觉/几何反馈，并校验目标一致性；行走期间仅用最近 6 秒的反馈修正目标，过期时沿用已有目标。异步捕获失败另存逐条 `capture_errors.jsonl`，包括最近的原始里程计样本，便于区分跳变、延迟和时序问题。

每阶段初始规划路径不超过 4.5 米，总初始规划预算 6.5 米；运动阶段仍受位移和累计行程预算限制，每阶段 Nav2 超时 210 秒。任何故障停止，不用额外停走次数掩盖失败。只取消本任务提交的 Nav2 目标。
